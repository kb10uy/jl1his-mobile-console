# 設計決定事項

[初期構想](initial-design.md) をもとに検討して決めた内容をまとめる。
「案」と書いた項目は未確定、消費電流・メモリ・CPU の数値はすべて概算で未実測。

## ハードウェア

### 構成部品

| 役割 | 部品 | 決定内容 |

| MCU | Raspberry Pi Pico 2 W | ピンヘッダー実装 |
| GPS レシーバー | [GYSFDMAXB](https://akizukidenshi.com/catalog/g/g109991/) | UART 接続、1PPS を配線、裏面に CR2032 を搭載 |
| 環境センサー | [BME280](https://akizukidenshi.com/catalog/g/g109421/) | I2C 接続 |

| 入力ボタン | タクトスイッチ | 4 個、ジャンパワイヤーで 6 個まで増やせる配置にする |

| リグ用 VBUS の電流制限 | [CH217K](https://akizukidenshi.com/catalog/g/g129464/) | SOT23-6 を DIP 変換基板に載せて実装 |
| 電源入力 | [USB Type-C DIP 化キット (シンプル版)](https://akizukidenshi.com/catalog/g/g113080/) | 5 V のみ |
| 基板 | [95x72mm ユニバーサル基板](https://akizukidenshi.com/catalog/g/g103054/) | |

### MCU に Pico 2 W を選ぶ理由

- PIO-USB が PIO を 1 ブロック専有し、Wi-Fi チップとの通信にも PIO が要る。RP2040 は 2 ブロックで使い切るが、RP2350 は 3 ブロックある。
- ドップラー補正の軌道計算 (SGP4) は倍精度演算で、RP2350 は FPU と倍精度コプロセッサを持つ。
- 必要量の概算は RAM 130 KB 程度、Flash 1 MB 弱。Pico 2 W は RAM 520 KB、Flash 4 MB。

### 電源

- 入力は USB-C の 5 V だけとする。PD のネゴシエーションはしない。
- CC1-GND 間と CC2-GND 間に 5.1 kΩ を 1 本ずつ入れる。DIP 化キットには載っていない前提で外付けする。
- USB-C の D+ / D− は未接続。
- 5 V 系は USB-C の VBUS から GPS、OLED、リグ用 USB-A に直接配る。
- Pico へは USB-C の 5 V からショットキーダイオード経由で VSYS (39 番ピン) に入れる。VBUS (40 番ピン) は未接続とし、書き込み用の micro-USB を同時に挿しても電源が衝突しないようにする。
- BME280 は 3V3(OUT) (36 番ピン) から給電する。
- リグ用 USB-A の VBUS には電流制限付きスイッチ IC の CH217K を入れる。
    - 制限値は 500 mA を想定し、ISET と GND の間に 120 kΩ を入れる (制限電流 = 60 k ÷ 抵抗値)。
    - VIN と VOUT にコンデンサを付ける。データシートの USB 用途での代表値は 120 µF。
    - EN# と FLAG# を GPIO につなぎ、VBUS の入れ直しと異常検出ができるようにする。
- IC-705 側は「USB Power Input (Phone, Tablet, PC)」を OFF にして使う。初期値は ON で、そのままだとこのデバイスから充電しようとする。
- 消費電流は常時 120〜170 mA 程度の見込み (リグ側 VBUS を除く)。

### リグ用 USB ホスト

- Pico-PIO-USB 方式で GPIO から USB-A メスに出す。Pico の micro-USB は書き込みとデバッグ用に残す。
- D+ と D− は連続する 2 本の GPIO を使う。
- GPIO 側に 22 Ω を直列に入れ、コネクタ側にプルダウン抵抗を付ける。
- システムクロックは 120 MHz にする。

### ピンアサイン (案)

Pico 2 W を micro-USB が基板の上端に来る向きで中央上寄りに置く前提。

| ピン | GPIO | 用途 | 配置 |
|---|---|---|---|
| 1, 2 | GP0, GP1 | GPS (UART0 TX / RX) | 左上 |
| 4 | GP2 | GPS 1PPS | 左上 |
| 6, 7 | GP4, GP5 | BME280 (I2C0 SDA / SCL) | 左端の中ほど |
| 14〜17 | GP10〜GP13 | ボタン 1〜4 | 下端 |
| 19, 20 | GP14, GP15 | ボタン 5〜6 用に空けておく | 下端 |
| 21, 22 | GP16, GP17 | OLED DC, CS | 右下 |
| 24, 25 | GP18, GP19 | OLED SCK, MOSI (SPI0) | 右下 |
| 26 | GP20 | OLED RST | 右下 |
| 29 | GP22 | CH217K EN# | 右上 |
| 31, 32 | GP26, GP27 | USB-A の D+, D− (PIO) | 右上 |
| 34 | GP28 | CH217K FLAG# | 右上 |

- 予備は GP3、GP6〜GP9、GP21 の 6 本。GP8 / GP9 は UART1 に使えるので、将来の有線 CI-V 用に残せる。
- USB-C、USB-A、CH217K は Pico の電源ピンに近い右上にまとめる。
- GPS アンテナは OLED の昇圧回路と Wi-Fi アンテナから離す。
- BME280 は発熱源から離して基板の端に置く。

## ソフトウェア

### 基盤

- Rust / embassy をベースとする。
- USB ホストは `embassy-usb-host` と `rp-pio-usb-host` を使う想定。前者には CDC-ACM、ハブ、CP210x のドライバがある。
- PIO-USB の約 1 ms 周期の keepalive は高優先度の executor で動かす。

### ワークスペース構成 (案)

細かく分けて、ハードウェアに依存しない部分を PC 上で単体テストできるようにする。

| クレート | 内容 | PC 上でのテスト |
|---|---|---|
| `civ` | CI-V フレームの組み立てと解析 (I/O なし) | 可 |
| `orbit` | 軌道要素の解析、SGP4、観測点からの距離変化率・方位・仰角 | 可 |
| `doppler` | トランスポンダのモデルと追尾の状態遷移 | 可 |
| `geo` | グリッドロケーター、NMEA の扱い | 可 |
| `ui` | 画面描画 | 可 |
| `config` | 設定と衛星データのスキーマ、直列化 | 可 |
| `firmware` | embassy のタスクとドライバの結線 | 実機のみ |

`firmware` には USB + CI-V、OLED、GPS、BME280、Wi-Fi AP をそれぞれ単独で動かす確認用バイナリを置く。

### リグ制御

- 最初の対応機種は IC-705 とする。USB は CDC-ACM、プロトコルは CI-V。
- 周波数とモードは 1 秒ごとにポーリングする。
- 接続時に DTR / RTS を両方とも落とす。リグ側で PTT やキーイングに割り当てられている場合があるため。
- ハブ + CP210x 構成のリグ (IC-7300 / 9700、Yaesu 各機種) は後回しにする。

### 設定と保存

- Wi-Fi AP はボタン操作で立ち上げる。常時は出さない。
- 軌道要素と衛星の周波数は WebUI から手動で入力する。ネットワーク経由の取得はしない。
- 設定と衛星データは Flash の末尾に置く。
    - リンカスクリプトで末尾の領域をコード配置の対象から外す。
    - 形式のバージョン番号を持たせる。ファームウェアを書き換えても領域は残るため。
    - 消去と書き込みの間は割り込みも他方のコアも止まり、PIO-USB の keepalive が途切れる。保存は WebUI で設定を確定したときだけ行い、追尾中には書かない。
    - 生の構造体を直接書かず、`sequential-storage` のようなキー・バリュー形式のクレートを使う。

## ドップラー補正

### 決定内容

- 送信と受信の両方を補正する。
- IC-705 ではスプリットを使い、VFO A を受信、VFO B を送信に割り当てる。CI-V のコマンド 25 で、VFO を切り替えずに両方の周波数を読み書きする。
- 初版の対象は FM 衛星とする。
- データ構造はリニアトランスポンダを含む形にしておく。FM は「幅ゼロで非反転のトランスポンダ」として扱い、計算部分を共通にする。

### リニアトランスポンダ対応で追加になるもの

1. トランスポンダの定義。アップリンクとダウンリンクの通過帯域、反転かどうか、上下のモードの組。
2. 「衛星上の周波数」の保持。通過帯域のどこを使っているかを状態として持ち、リグの送受信周波数を毎回そこから計算する。反転型は上下の和が一定、非反転型は差が一定。
3. ダイヤル追従。運用者が受信ダイヤルを回した分だけ 2 の状態を動かし、送信側を連動させる。CI-V トランシーブを使えばポーリング周期を上げずに済む。
4. 書き込み頻度の分離。435 MHz 帯では天頂通過の前後に毎秒 160 Hz 程度動くので、読み取りは 1 秒周期のまま、書き込みは誤差がしきい値を超えたら行う。
5. 時刻精度。1 秒のずれが最大 160 Hz 程度の誤差になるため、1PPS で合わせる。
6. 衛星ごとの手動補正オフセット。

IC-705 は送受同時ができないので、送信中に自分のダウンリンクを聞いて合わせ込むことはできない。

## 対象外としたもの

- OLED 基板上の microSD
- PD ネゴシエーションと 5 V 以外の電源入力
- 軌道要素のオンライン取得と TLS
- FTDI / CH34x / PL2303 の USB シリアル変換ケーブル経由の接続
- 有線 CI-V / TTL CAT 端子 (予備ピンだけ確保する)

## 未決・要確認

- CH217K の EN# の極性、ピン配置、500 mA 付近での制限精度。データシート本文で確認する。
- IC-705 と PIO-USB 経由で CI-V が通るか。使用するクレートはどれも 0.1.0 台で、最初に実機で確認する。
- 送信中に送信側 VFO の周波数を書き換えられるか。
- USB ホストのプルダウン抵抗値。RP2350 の A2 ステッピングは E9 エラッタにより 15 kΩ では足りない可能性がある。手元の個体のステッピングと合わせて確認する。
- IC-705 の USB Power Input を ON のままつないだとき、電流制限が働いて切断と再接続を繰り返さないか。
- 部品の寸法図と基板の穴数の照合。特に右列に USB 基板 2 枚と OLED が縦に収まるか。
